# 曹金玉扩展技能排错记录

> 武将：金玉大帝（自定义扩展）
> 技能：无限制隅泣（基于原版隅泣，去除每回合次数限制）
> 日期：2026-04-06

---

## 目标

基于原版隅泣，制作一个无每回合次数限制的独立版本。

## 踩过的坑

### 1. 直接删除 `usable: 2` 无效

**现象**：删除 `usable: 2` 后技能行为未改变。

**原因**：项目使用 vite 构建，运行的是 `dist/` 下的编译产物。扩展文件位于 `apps/core/extension/` 下，通过动态 `import()` 加载。需要确保：

- 编辑的是正确的源文件（`apps/core/extension/无名扩展/extension.js`），不是 `docs/skills/` 下的文档副本
- 编辑后刷新游戏页面（Ctrl+Shift+R 强刷清除缓存）

**结论**：`usable: 2` 删除本身是正确的做法。框架在 `library/index.js` 中的判断逻辑为：

```js
if (info.usable !== undefined) {  // undefined 时整段跳过
    if (player.getStat("triggerSkill")[skill] >= num) return false;
}
```

`usable` 不存在时，框架不做任何使用次数检查，也不递增计数器。

### 2. 存储键独立后技能参数无法成长

**现象**：将 `player.storage.yuqi` 改为 `player.storage["无限制隅泣_data"]` 后，UI 能正常显示，但只能分配1张牌给目标、1张给自己，参数永远停留在初始值 `[0, 3, 1, 1]`。

**原因**：角色仍然使用原版 `shanshen`（善身）和 `xianjing`（娴静）。这两个技能内部写死了通过 `get.info("yuqi").getInfo(player)` 来读取和修改 `player.storage.yuqi`：

```js
// shanshen / xianjing 的 content 中：
const name = "yuqi";
const list = get.info(name).getInfo(player);
list[index] = Math.min(5, list[index] + 2);  // 修改的是 player.storage.yuqi
player.markSkill(name);
get.info(name).init(player, name);
```

当自定义技能使用独立的存储键后，善身/娴静修改的是 `player.storage.yuqi`，而自定义技能读取的是 `player.storage["无限制隅泣_data"]`，两者完全脱节。

**结论**：存储键必须保持 `player.storage.yuqi`，除非同时制作自定义版本的善身和娴静。

### 3. `skill_id: "yuqi"` 的作用

`skill_id` 是框架用于标识技能的元数据属性，主要影响：

- 音频文件查找路径
- 框架内部的 `info.skill_id ??= skillId` 默认赋值

删除 `skill_id: "yuqi"` 后，框架默认使用技能名 `"无限制隅泣"` 作为 `skill_id`。这不会影响技能的核心功能（触发、content 执行、存储读写），但会导致音频查找路径变化（从 `yuqi/` 变为 `无限制隅泣/`），扩展中无对应音频文件时静默失败。

---

## 最终方案

| 改动项 | 最终状态 | 说明 |
|--------|---------|------|
| `usable: 2` | 删除 | 解除次数限制 |
| `lib.skill.yuqi` (6处) | → `lib.skill["无限制隅泣"]` | 自引用，脱离原版技能定义 |
| `"skill_id": "yuqi"` | 删除 | 不再关联原版 |
| `player.storage.yuqi` | 保留 | 善身/娴静依赖此键 |
| 技能描述 | 删除"每回合限两次。" | 与实际效果一致 |

### 关键约束

**存储键不能独立**：只要角色继续使用原版 `shanshen`/`xianjing`，`getInfo` 就必须读写 `player.storage.yuqi`。要完全独立，需要同时自定义善身和娴静，将其中所有 `get.info("yuqi")` 替换为 `get.info("无限制隅泣")`。
